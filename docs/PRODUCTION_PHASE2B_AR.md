# المرحلة 2B — سلطة Core المشتركة، دمج المناطق والرسم، وتبريد الرسائل

التاريخ: 2026-10-31. الفرع: `arena/ce90627f-terad`.

## النتيجة وحدودها

أضيف **مسار ترحيل موحد اختياري**. عند تفعيله تصبح حالة القرار الحالية BUY/SELL/WAIT مشتقة من سجل Core المؤكد؛ لا يستطيع Tactical أو RXN أو انحياز الفريم إنشاء اتجاه دخول. هذا ليس إعادة كتابة لمحرك الأوامر ولا ضمان جاهزية إنتاج. لا تُفعّل الأوامر تلقائيًا، ولا تتحول درجة الأدلة إلى احتمال نجاح.

لم تبدأ المرحلة الثالثة أو الرابعة. الفجوات المذكورة أدناه صريحة، ولا يُدعى إغلاق كل عناصر التدقيق بمجرد نجاح الاختبارات.

## التفعيل

انسخ **كل** ملفات `MQL5/Include/QSMC` إلى مجلد Data Folder المقابل، بما فيها `QSMC_UnifiedDecision.mqh`، ثم اجمع المؤشر بـF7.

| المدخل | الافتراضي | الوظيفة |
|---|---|---|
| `InpUnifiedDecision` | `false` | تفعيل ترحيل القرار ودمج المناطق والرسم؛ false يحفظ المسار السابق |
| `InpUnifiedMergeATR` | `0.15` | سماحية دمج مناطق/إسقاطات من الجانب نفسه كنسبة ATR |
| `InpMessageCooldownBars` | `10` | تبريد رسائل التشخيص الموصولة؛ 0 يعطل منع التكرار |

لا يلزم تفعيل `InpUseFinalResolver` أيضًا: المفتاح الجديد يشغّل المستهلك المشترك بنفسه. إذا كان الاثنان مفعّلين، فالمسار الموحد هو صاحب الأولوية. لا يتغير مفتاح قائم أو preset بصمت. إبقاء الافتراضي false مقصود حتى اختبار توافق المنصة، وليس حذفًا للميزة.

القيمة غير الصالحة لسماحية الدمج ترجع إلى 0.15، ونطاقها المقبول 0..1. cooldown يُحد إلى 1000؛ الصفر أو السالب يوقف التبريد. هذه ليست توصيات معايرة مالية.

## 1. توحيد سلطة القرار

الملف الجديد: `MQL5/Include/QSMC/QSMC_UnifiedDecision.mqh`.

- `UD_Update` يقرأ فقط تأكيدات Core التي أصبحت متاحة عند بداية الشمعة التالية، مع confirmation_bar يساوي الشمعة المغلقة، ويأتي بعد created_bar.
- لا تأكيد Core في هذه الشمعة = **WAIT**، حتى لو كانت كل الأدلة الاستباقية BUY أو SELL.
- تأكيدات Core متضادة في الشمعة نفسها = **WAIT** مع سبب تعارض.
- النتيجة في `SUnifiedDecision`: وقت الشمعة، direction من -1/0/+1، score من 0..100، وأسباب قابلة للقراءة.
- الدرجة: Core المؤكد 60، توافق HTF +10، Reaction مغلقة موافقة +15، Tactical مغلق موافق +15. الأدلة لا تقلب أو تلغي Core؛ التعارض بينها سياق، وليس سلطة بديلة. الدرجة وصف أدلة، وليست حد تنفيذ إضافيًا.
- يُبنى snapshot قبل اختيار dispatcher. اختيار primary والتنبيه الاتجاهي في المسار الموحد لا يسمح لمرشح غير Core بامتلاك الاتجاه.
- root tactical النهائي يتلقى authoritative-pending عند تفعيل الترحيل، فلا ينشئ تنبيه دخول مستقلاً عن Core.
- `ResolveFinalSignal` وSTATUS ودرجة primary الظاهرة يستهلكون snapshot نفسه. معلومات RXN التي تبقى ظاهرة تحمل بادئة **CONTEXT**، وTactical يستخدم INFO بدل CONFIRMED المستقلة.
- لم تُغيَّر buffers أو مؤشرات iCustom أو تشخيص CORE أو قراءة EA القديمة. التنفيذ ما زال من حق Core القائم وحده؛ لا تضاف أوامر في الملف الجديد.

### حدود مهمة للسلطة المشتركة

عقد EA الحالي ودرجته الداخلية لم يُستبدلا بعقد جديد، ولا توجد معاملة ذرية جديدة تعيد توجيه جميع آثار Core السابقة على الرسم والتنبيه. المسار الجديد يطابق سجل Core المؤكد ويمنع منافسة الطبقات المساندة في root/dispatcher والعرض الحالي؛ لا يدّعي إعادة كتابة كامل دورة النشر التاريخية. إذا أُريد تغيير gate التنفيذ نفسه أو score الخاص بالـEA، فيلزم ترحيل منفصل واختبار buffers/الأوامر داخل MT5. لا يجوز وصل درجة 60–100 هذه مباشرة بحجم صفقة أو ادعاء احتمال نجاح.

## 2. دمج المناطق والرسم

- بقي محرك ZRE السابق كما هو عند تعطيل الترحيل.
- عند التفعيل تُجمع قوائم المناطق المحتفظ بها: out وdropped وtail، ثم تُدمج المناطق المتداخلة أو الأقرب من سماحية ATR إذا كانت من الجانب السببي نفسه.
- دمج سلاسل A–B–C متعدٍّ وثابت بترتيب geometry canonical. لا دمج لدعم مع مقاومة لمجرد التقارب.
- تحفظ بيانات أقوى منطقة؛ تعاد حدود الاتحاد وهويته ومصادره. القوة = أقوى قوة متاحة، وليست جمع نقاط مصطنعًا.
- تُعاد **حسابات حلقات اللمس** على الاتحاد؛ لا تجمع touch counts المتداخلة. العمر يصبح غير معروف إذا كان عمر أحد المكونات غير معروف.
- يعاد تطبيق min-score وrender cap بعد الدمج. النظام يدمج المناطق التي احتفظت بها القوائم السابقة؛ لا يسترجع مرشحين حُذفوا قبل تلك القوائم.
- يُربط مسار ZRE بالاتحاد الحالي، ثم يُعرض ممثل واحد لكل اتحاد/جانب: الأعلى score، ثم الأحدث عند التعادل. يستمر البحث عن ممثل أقوى حتى بعد امتلاء ميزانية العرض، دون تجاوز `ZRE_MAX_PATHS`.
- RXN كان يعرض BEST واحدًا؛ لم تُحذف طبقة RXN ولا أدوات OB/FVG/SR العاملة.

هذه السياسة تعالج مناطق ZRE ومساراتها الحالية، وليست أمرًا بحذف كل ملصقات OB/FVG/SMC أو كائنات مؤشرات أخرى. التاريخ الذي لم يعد له اتحاد حالي يعود إلى مقارنة الحدود المباشرة. لا يوجد ادعاء بأن الصورة القديمة أصبحت خالية من كل ازدحام دون Objects list واختبار الشارت الفعلي.

## 3. منع تكرار الرسائل

`UD_LogAllows` يمنع تكرار المفتاح نفسه خلال N شموع فعلية عبر `iBarShift`، وليس N دقائق؛ وبذلك لا تُحسب عطلة السوق شموعًا وهمية.

المسارات الموصولة الآن:
- `LogLifecycle` — نفس النص.
- `DebugLogSignal` — هوية محتوى الرسالة (الاتجاه والمنطقة والأسعار وOHLC والسبب والحالة).
- طباعة `PMI_LogEvent` — نفس النوع والنص. السجل الداخلي للأحداث لم يُحذف؛ التبريد للطباعة فقط.

الذاكرة محدودة بـ128 مفتاحًا. لا يُطرد مفتاح حي لإفساح مكان لمفتاح جديد؛ عند الامتلاء تُحجب مفاتيح جديدة حتى انتهاء نافذة خانة. هذا يحفظ ضمان عدم التكرار مقابل احتمال فقد رسائل debug جديدة في حالة الضغط. فقد موضع timestamp من التاريخ يُعامل بتحفظ ولا يجعله منتهيًا افتراضيًا. الرجوع بالوقت يفرغ الخانات المستقبلية.

**ليست طبقة عالمية لاعتراض جميع Print في المشروع.** رسائل التهيئة والأخطاء الصحية والتحذيرات وسجل صفقات/نتائج الاختبار والتنبيهات لها سياساتها القائمة؛ لم تُخفَ خلف cooldown عام. إذا كان المطلوب توحيد كل logging call-site، فذلك جزء متبقٍ من التقوية، ويحتاج تصنيف critical/debug قبل التوصيل. تبريد تنبيهات popup/push القائم لم يُخفف.

## 5. الملفات والتسليم

التعديل البرمجي الرئيسي في `nadir2.mq5`، والـheader الجديد أعلاه. تعديلات الاختبارات القائمة تخص عقود الترحيل المعلنة وعدّ الأسطر/includes/braces، لا إزالة حالات حماية أو إضعاف gates. حدث توثيق layout وrelease gate ليشملا الملف الجديد.

`docs/PHASE2B_HOST.diff` يحتوي فرق المضيف من بداية هذه الدفعة. حزمة `phase2b-delivery.zip` تتضمن النسخ الكاملة الحالية للملفات المعدلة/الجديدة في هذه الدفعة، بما فيها الاختبارات والتوثيق. هي حزمة مصادر للمراجعة فوق المستودع، وليست EX5 أو مثبتًا مستقلًا.

## 6. شرط قبول MT5 — متبقٍّ إلزاميًا

لم يُشغّل MetaEditor أو MT5 هنا؛ لا ادعاء **zero errors / zero warnings** قبل إرفاق build log.

1. نسخة احتياطية للـEX5 و.set؛ نسخ headers كاملة؛ F7 للمؤشر ثم مراجعة 0 errors و0 warnings.
2. حساب demo فقط، XAUUSD M1/M15/H1، مؤشر واحد لكل شارت. قارن أولًا `InpUnifiedDecision=false` بالنسخة السابقة؛ buffers/أوامر Core يجب ألا تتغير.
3. فعّل `InpUnifiedDecision=true` في نسخة تجريبية: تأكد أن STATUS والسبب والدرجة لا ينشئون اتجاهًا دون سجل Core مؤكد جديد في الشمعة المغلقة.
4. جرّب Preview وReaction مضادة/مزدوجة مع Core مؤكد؛ يجب ألا تصنع الطبقات المساندة أمرًا أو تعكس اتجاه Core. احتفظ بمقارنة الوقت بين Core buffer وsnapshot وprimary.
5. التقط Objects list قبل وبعد الدمج؛ راقب الاتحاد والأقوى وعد اللمسات، والدعم مقابل المقاومة، وتغير الهوية عند تغير الاتحاد. لا تقارن screenshot وحدها.
6. فعّل diagnostic logging مؤقتًا، واختبر N=0 و1 و10، وفقد التاريخ وتحديثه، وعدد الرسائل؛ أعد debug إلى off بعد الاختبار.
7. أعد تحميل التاريخ وغيّر الفريم وأزل المؤشر. اختبر full rebuild وincremental ومدة 24 ساعة مع قياس زمن OnCalculate والذاكرة وعدد الكائنات. الدمج الإضافي له تكلفة يجب قياسها على تاريخ وإعدادات الوسيط.

## المخاطر المتبقية

لم تُصلح هذه الدفعة تعريف EQH/EQL المنفرد (A04)، ولم تعاير الدرجات ماليًا. دمج الاتحاد قد يكبّر المنطقة ويغير id/حالة lifecycle عند opt-in؛ لذلك لا يُستبدل preset حي قبل replay. المسار الموحد ليس إذن نشر live قبل التجميع والاختبار التجريبي. الجاهزية الإنتاجية النهائية ما زالت مشروطة بتلك الأدلة.
